## 独立性与判定原则

1. 只以目标目录中的实际交付物、可复现命令输出和人工审阅证据为准；开发报告中的“已完成/已通过”声明不能替代测试证据。
2. 复验前重新读取适用的 `AGENTS.md`（若届时新增）、完整文件清单和 Git 状态，不能沿用本清单建立时的空仓快照。
3. 状态只使用：`PENDING`、`PASS`、`FAIL`、`BLOCKED`、`N/A`。`N/A` 必须有与阶段 0 范围一致的理由。
4. 所有“硬门槛”均为必过项。任一硬门槛 `FAIL/BLOCKED`，或存在未关闭的阻断级缺陷，都不得给出阶段 0 通过结论。
5. 阶段 0 允许文档、图、示例和机器可读契约；不允许业务实现、可运行产品骨架、真实凭据或真实/生产数据。
6. 公共接口与枚举中的决定必须在阶段 0 内闭合。实现细节可以留待后续阶段，但不得以 `TBD/TODO/待定/后续决定` 推迟会影响调用方、解析器或报告消费者的契约决定。

## I. 禁止内容与负向门槛（硬门槛）

### ST0-I01 不得出现业务代码

- [ ] 除文档、图、schema、OpenAPI/YAML 契约和纯示例外，不存在应用入口、服务实现、领域逻辑、数据访问层、可部署基础设施、产品运行脚本或编译产物。

- [ ] 不存在依赖安装、产品启动、部署或连接外部服务所需的真实配置。

### ST0-I02 不得出现真实凭据

- [ ] 文件名和正文均未发现 `.env`、私钥、证书私钥块、访问 token、API key、密码、连接串或带认证信息的 URL。

### ST0-I03 不得出现真实数据

## 开发交付后的复验步骤与证据

以下命令仅作为复验计划；执行时应记录完整命令、时间、退出码和必要输出，不可只抄结论。

1. 规则与工作树：重新查找所有父级/子级 `AGENTS.md`，运行 `git rev-parse`、`git status --short --branch`（若仍非 Git 工作树，记录事实并依据阶段 0 交付要求判定是否阻断）。
2. 清单与类型：使用 `rg --files -uu -g '!**/.git/**'` 建立完整文件清单，并按扩展名/目录人工识别潜在业务代码、二进制和生成物。
3. 必需文件：逐一确认 LICENSE、`.gitignore`、README、charter、威胁模型、taxonomy、治理/边界、数据流、五类契约和三类模板。
4. 未决项扫描：搜索 `TODO|TBD|FIXME|XXX|待定|暂定|后续决定|示意|placeholder`，逐项判定是否影响公共接口或枚举。
5. 凭据扫描：搜索私钥头、常见 token/key/password/secret/credential/connection-string 模式、带用户信息的 URL 和 `.env` 类文件；正则扫描结果必须人工复核。
6. 真实数据审阅：搜索邮箱、电话、身份证/护照样式、真实域名/IP、个人绝对路径、组织/客户名和日志记录；确认所有例子均为明确的合成数据。
7. 契约解析：使用本机已有且不修改仓库的解析器验证 YAML/JSON/OpenAPI/schema；若缺少解析器，记录 `BLOCKED`，不能据肉眼直接判通过。
8. 链接与引用：解析 Markdown 相对链接、schema `$ref`、错误码/指标/枚举/威胁 ID 的定义与引用，报告断链、重复和孤儿定义。
9. 顺序一致性：提取所有 guarded 阶段序列并逐项比较；任何文档或示例出现不同顺序、缺步、别名漂移或可静默绕过均判失败。
10. baseline 边界：全文检索 network/cloud/remote/API/database/telemetry/production/real-data/credential 等概念，确认任何提及均为明确禁止、风险说明或阶段外内容，而非 baseline 允许行为。
11. 交叉审阅：对公共字段和枚举建立定义-引用矩阵，确认类型、默认值、空值、未知值、错误和版本行为完整且一致。
12. 记录结果：在独立测试报告中逐项写入 `PASS/FAIL/BLOCKED/N/A`、证据路径/行号、命令退出码和缺陷编号，再由架构角色作最终验收。

## 最终通过条件

只有同时满足以下条件，独立测试方才可建议阶段 0 通过：

1. A 至 J 的所有硬门槛均为 `PASS`，或极少数真正不适用项有充分的 `N/A` 证据。
2. 公共接口、枚举、guarded 固定顺序和 baseline 本地纯合成边界没有未决决定或跨文档冲突。
3. 阶段 0 文件中没有业务实现、真实凭据或真实/生产数据。
4. 所有机器可读契约可解析，文档链接和交叉引用有效。
5. 阻断级/高严重度缺陷为零，其他已知问题不改变阶段 0 契约或安全边界，并被明确记录为残余风险。
6. 测试结论绑定到明确的文件快照或 Git 提交；开发完成前的本清单不构成该结论。
